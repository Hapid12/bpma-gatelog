================================================================================
                              RELASI ANTAR ENTITAS
================================================================================

+------------------------------------------------------------------------------+
|                    RELASI: EMPLOYEE - PACKAGE (One to Many)                  |
+------------------------------------------------------------------------------+
|                                                                              |
|   +-----------+          menerima          +------------+                    |
|   | EMPLOYEE  |----------------------------| PACKAGE    |                    |
|   +-----------+          1 : N             +------------+                    |
|                                                                              |
| Deskripsi:                                                                   |
| - Satu Employee dapat MENERIMA banyak Package (1:N)                          |
| - Satu Package hanya diterima oleh satu Employee                             |
| - Foreign Key: penerimaPaket pada entitas Package merujuk ke _id Employee    |
|                                                                              |
| Kardinalitas:                                                                |
|   EMPLOYEE (1) ←──────────────────→ (N) PACKAGE                              |
|                                                                              |
+------------------------------------------------------------------------------+


+------------------------------------------------------------------------------+
|                    RELASI: EMPLOYEE - VISITOR (One to Many)                  |
+------------------------------------------------------------------------------+
|                                                                              |
|   +-----------+          dikunjungi        +------------+                    |
|   | EMPLOYEE  |----------------------------| VISITOR    |                    |
|   +-----------+          1 : N             +------------+                    |
|                                                                              |
| Deskripsi:                                                                   |
| - Satu Employee dapat DIKUNJUNGI oleh banyak Visitor (1:N)                   |
| - Satu Visitor mengunjungi satu Employee (melalui targetEmployee)            |
| - Relasi: targetEmployee pada entitas Visitor merujuk ke nama Employee       |
|                                                                              |
| Kardinalitas:                                                                |
|   EMPLOYEE (1) ←──────────────────→ (N) VISITOR                              |
|                                                                              |
| Catatan:                                                                     |
| - Relasi ini menggunakan nama employee (String) bukan ObjectId               |
| - Disarankan untuk mengubah ke ObjectId reference untuk integritas data      |
|                                                                              |
+------------------------------------------------------------------------------+

================================================================================
                    DEFINISI PRIMARY KEY & FOREIGN KEY
================================================================================

PRIMARY KEYS (PK):
------------------
1. Employee._id    → ObjectId (Auto-generated oleh MongoDB)
2. Package._id     → ObjectId (Auto-generated oleh MongoDB)
3. Visitor._id     → ObjectId (Auto-generated oleh MongoDB)


FOREIGN KEYS (FK):
------------------
1. Package.penerimaPaket → Merujuk ke Employee._id
   - Tipe: ObjectId
   - Referensi: Employee collection
   - Constraint: One Package → One Employee (Many-to-One dari sisi Package)

================================================================================
                              CATATAN TAMBAHAN
================================================================================

1. NORMALISASI:
   - Database menggunakan MongoDB (NoSQL) dengan struktur semi-normalized
   - Field 'penerimaNama' pada Package merupakan denormalisasi untuk 
     mempercepat query (tidak perlu JOIN/populate untuk menampilkan nama)

2. INTEGRITAS REFERENSIAL:
   - Package.penerimaPaket memiliki referensi ObjectId ke Employee
   - Visitor.targetEmployee menggunakan String (nama), disarankan untuk 
     mengubah ke ObjectId reference untuk integritas data yang lebih baik

3. TIPE DATA MONGODB:
   - ObjectId: ID unik 12-byte yang di-generate otomatis oleh MongoDB
   - String: Teks/karakter
   - Number: Angka
   - Date: Tanggal dan waktu

4. REKOMENDASI PERBAIKAN:
   - Ubah Visitor.targetEmployee dari String ke ObjectId dengan referensi 
     ke collection Employee untuk menjaga integritas referensial
   - Tambahkan indexing pada field yang sering di-query (nomorResi, email)
